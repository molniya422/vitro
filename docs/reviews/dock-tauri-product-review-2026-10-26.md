# Dock Tauri 产品级审查与后续建议

> 日期：2026-10-26  
> 对象：`D:\dockyh\dock-tauri` 当前工作区  
> 范围：产品边界、现有功能、交互和平台风险、美术与动效方向、素材策略、开发顺序和验收标准。  
> 证据说明：结论来自当前源码、仓库文档、`docs/research` 设计资料和本轮测试记录。没有取得本轮 Tauri 实机截图，因此美术意见属于源码审阅与设计建议，不是对最终画面的视觉验收。

## 结论

`dock-tauri` 有值得继续使用的底层基础，但当前仍是 Dock 原型与桌面行为验证项目，不能视为可发布的桌面增强套件。Rust 的几何、自动隐藏、点击命中和设置持久化已有较完整的纯函数测试；React 已形成 Dock、Launchpad、系统监控和设置页。主要风险在于：当前工作区前端生产构建失败；运行中的应用无法通过 Dock 聚焦或还原；隐藏热区可能干扰 Windows 任务栏；产品范围与已确认的套件边界不一致；视觉主题和预览仍不足以代表目标成品。

建议保留现有项目，先修好构建和 Dock 的真实桌面行为，再按模块逐步扩展。不要把功能图标、单元测试通过或旧 MSI 存在当成产品可交付的证明。

## 产品边界与定位

目前有效的目标应按后续确认的**独立 Windows 桌面增强套件**理解，早先的“独立 Dock 软件”范围已不足以代表最终目标。目标套件包括 Dock、Launchpad、应用与窗口/任务管理、Shelf、系统托盘、Docklet 安装与权限管理、设置。系统监控可以作为内置 Docklet 或可选面板，不应让它挤占最常用的 Dock 空间。

套件应与 Windows 任务栏共存，自动隐藏是用户可选项。Glassboard 的既有能力继续由原产品保留，不混入 Dock 套件发布包。Nexus、BitDock 和 GlassDesk 可用于理解用户行为、交互和模块组织；需要独立实现，不复制其代码、品牌、图标或未授权素材。Vitro 源码不作为本评审依据。

当前 Tauri 规格将项目写成独立 Dock，并明确把 Shelf、托盘镜像、Docklet 等推迟；这与后续套件范围存在产品定义冲突。应以本文件开头的目标作为产品范围基线，再修订相应设计规格和 README/HANDOVER，避免不同文档继续指导不同产品。

建议对外定位为：**保留 Windows 桌面和任务栏工作方式、提供 macOS 风格 Dock 与可组合桌面工具的轻量套件**。视觉上借鉴 macOS 的克制、层次、图标反馈和空间动画，不把 Windows 伪装成 macOS，也不接管 Explorer 或替换系统任务栏。

## 最高优先级产品问题

### P0：先恢复可信构建与验证链

1. 修复 `Dock.tsx` 的 TypeScript 错误：要么把指针按下、阈值拖动、重排预览和松手提交完整接入，要么删除未接入的拖拽状态/导入，避免留下“界面支持拖动”的假象。
2. `npm run build`、Tauri 前端嵌入构建都要成功；测试需固定版本和运行环境。
3. 修正 README/HANDOVER 的测试数、特性清单、性能数据日期和打包步骤。当前 README 测试数写 58，实际已是 66。
4. 将本轮当前源码和重新构建的安装包分开说明。已有 MSI 记录不能替代当前工作区的 Release 构建验证；sidecar 需实际完成冻结、打包和启动测试。

### P1：完成“点 Dock 就能管理应用”的核心闭环

Dock 点击行为需要以真实窗口快照为准：应用未运行则启动；只有一个窗口且已最小化则还原并置前；窗口已打开则聚焦；多个窗口时显示窗口选择器或清楚的窗口列表。添加失败、已卸载、权限受限都要显示可恢复的错误，不应静默吞掉 Promise 错误。

为此，窗口跟踪模型应包含稳定的窗口 ID/句柄、应用身份、标题、可见/最小化状态和显示器；激活/还原动作单独走平台层。对同名程序的文件名兜底匹配应标识歧义，后续以 AUMID/MSIX identity 补足 Store 应用，不要误把同名程序合并。

应用目录需要递归枚举 Start Menu 文件夹并支持刷新；为添加普通 exe、Store 应用和用户自选快捷方式定义明确入口与身份。移除 Pin 只应解除 Dock 固定，不应被误解为卸载程序。

### P1：验证 Windows 任务栏共存

自动隐藏建议首次安装默认关闭，用户显式启用后再显示提示和延迟参数；现代码默认值为开启，Tauri 规格则写关闭。隐藏状态的触发热区须尽可能薄、可预测且不截断系统任务栏输入。

最低限度要实测：任务栏自动/始终显示两种状态；Dock 与任务栏同为置顶时的 Z 序；屏幕下沿点击透传；Win+D、全屏独占/无边框全屏、Explorer 重启和 DPI 切换；恢复设置页后不会卡在显示状态。必要时调整热区模型，别把“2px 全宽窗”仅凭单元测试判定为安全。

### P2：按模块逐步形成套件

| 模块 | 应交付的实用闭环 | 依赖与边界 |
|---|---|---|
| Dock | Pin 管理、分区、拖拽重排、启动/聚焦/还原、多窗口选择、右键操作、可选自动隐藏 | 与任务栏共存；退出入口必须总能找到 |
| Launchpad | 完整应用库、搜索、类别/文件夹、Pin/启动、失效项处理、键盘导航 | 首先确保应用发现和身份模型；大目录搜索保持响应 |
| 窗口/任务管理 | 列出所有可切换窗口，显示应用/标题/最小化状态，点击激活 | 使用窗口 ID 与平台 API；不以进程列表冒充窗口列表 |
| Shelf | 可视化临时收纳文件/链接、拖入与拖出、打开/移除、持久化策略 | 与应用 Pin 区分；文件操作要明确是引用还是复制 |
| 系统托盘 | 显示真实托盘图标、保留原始上下文菜单和通知区行为 | 不复制或接管 Explorer；先验证不同 DPI 与隐藏溢出图标 |
| Docklet | 安装、启停、版本/来源、权限说明与撤销；先随产品发布少量官方插件 | 外部插件不能任意访问文件/网络/进程；窄 API、权限清单与资源限制先于商店 |
| 设置 | 外观预设、任务栏/自动隐藏、显示器、Dock 项、插件权限、启动/退出、诊断 | 简单项优先，复杂参数放高级选项；中英文界面和键盘操作纳入验收 |

不建议一次做完所有模块。每一阶段都应可安装、可退出、数据能保存、异常能恢复，再继续扩大范围。

## 美术与动效意见

以下都基于 CSS/React 源码、研究规格与产品目标推导，需通过多背景桌面截图复核。

### 当前已有的优点

- Dock 几何基线合理：默认图标 48px、图标间距 8px、水平内边距 16px、垂直内边距 10px、药丸半径 34px，与 macOS 研究基线接近。
- 图标从 Windows Shell/Start Menu 按 DPI 提取，优先保留真实应用标识；图标快照缓存和懒加载也有性能价值。
- Dock 玻璃 pill 没有外描边/外投影，而是用内高光和内阴影建立厚度；运行点、Tooltip、按压反馈和可调反射已形成视觉骨架。
- 有 macOS 克制与弹性两种 profile 的基础概念，可发展成清楚的主题/动效预设。

### 需要优先改善的观感

1. **材质应明确区分“真模糊”和“绘制玻璃”。** 当前 pill 是固定深色填充、渐变和内阴影，没有桌面背景模糊。此处理论上更像有色半透明片，不是 Liquid Glass。先做限定在 pill 形状内的 DWM Acrylic 探针；如果模糊会污染透明 headroom、反射区或点击穿透，就采用精致绘制玻璃并如实命名，不要只通过降低透明度宣称真模糊。
2. **噪点要避免规则点阵和缩放摩尔纹。** 当前 `radial-gradient` 以 3px 重复、透明度 0.0025。研究基准是低对比 128px 周期的噪点纹理。建议用非显眼的预生成纹理或其它无明显重复的方案，并比较 100/150/200% DPI 和亮暗壁纸；只有截图证明点阵可见或形成干扰时再加深纹理。
3. **把默认动态效果改得克制。** Rust 默认 profile 为 `vitro`、放大峰值 1.6、自动隐藏开启；而用户目标偏 macOS，研究规格的 macOS profile 峰值为 1.2、淡入淡出更克制。建议默认选 Sonoma/Calm：放大峰值约 1.2、约 200ms 进入/250ms 退出、无回弹；弹性档作为主动选择。当前 `macos` profile 只影响放大计算，CSS 时长/缓动仍统一，需让峰值、曲线、持续时间成为完整 token。
4. **系统“减少动态效果”必须优先于应用档案。** CSS 的 `prefers-reduced-motion` 不能单独停掉 React 指针位置驱动的放大。监听操作系统偏好，并与设置页选项合并；减少动态效果时停用或明显压低放大/弹跳/进场，保留可见的状态反馈。
5. **重新审视最小化数量的红色角标。** 当前 minimised 数量使用红色，这容易表达成未读通知或警告。建议红色保留给真实通知；窗口数用中性药丸/低饱和文本，窗口预览再承担管理功能。
6. **设置预览必须展示真实结果。** 当前 DockPreview 使用 A/B/C 和 Unicode 符号，无法反映真实 Shell 图标、控制图标、遮罩或壁纸对比。改为读取当前 Pin 的真实图标；图标加载失败时使用统一、有意设计的占位图标。预览至少能看到 Sonoma、Tahoe、浅色主题的实际材质和运行状态。
7. **统一系统图标的视觉重量。** Explorer/Settings/Launchpad/Monitor 等功能入口目前是小型单线 glyph，应用入口则是完整彩色图标。重新制作一套一致的系统入口图标（光学尺寸、笔画、底板和留白一致），避免控制入口像细线按钮、应用图标像厚重贴纸。
8. **对图标圆角和阴影做背景校准。** 应用图标 20–22% 圆角可作为预设，但不宜默认裁掉每个应用的原生标志边缘；按主题选择原图、圆角 mask 或底板。`drop-shadow` 是否好看要在明亮、深色、高饱和壁纸上验证，避免图标浮成一排贴纸。
9. **分开通知、窗口状态和普通数值。** 运行点、最小化数、Docklet 未读数用固定语义：运行点只表“在跑”，中性数字只表窗口数，红色角标只表真正待处理通知。避免把不同意义都画成红徽章。
10. **让设置页先提供策展好的预设。** 初级用户只需看到 Sonoma Calm、Tahoe Float、Minimal 等少数清晰预设，以及尺寸/放大/自动隐藏等常用值；材料 opacity、圆角等细滑杆放到 Advanced。主题不能只是一堆互相无关的数值。

### 建议的美术方向

默认做 **Sonoma Calm**：深色与浅色分别设计，单一强调色、半圆药丸、清楚的图标底对齐、克制的运行点和无回弹放大。另提供：

- **Tahoe Float**：更轻的填充、更悬浮的留白与清晰边缘光；只在 pill 范围真实裁切可靠时启用真实 blur/refract。
- **Minimal**：尽量弱化材质，保留图标、运行态和空间反馈，适合不想模仿玻璃的用户。
- **Windows Acrylic**：按系统浅/深主题适配，保持 Windows 控件与键盘行为一致。

三个方向使用同一套图标与间距规范，改变材质、强调色和动效，不为每套主题重新发明布局。避免泛蓝渐变填满界面、每个图标加卡片底、过重发光和所有控件统一的弹跳动画。

### 美术资源分配

| 资源类别 | 推荐来源 | 使用约束 |
|---|---|---|
| 用户电脑上的应用图标 | 当前 Shell/快捷方式实时提取；按实际 DPI 缓存 | 仅本机显示；不把第三方程序图标打包进产品 |
| Dock 品牌、安装包图标、产品空状态 | 自行设计一套原创母版与尺寸变体 | 建立作者、源文件、导出尺寸和授权记录；禁止先用字母代替成品 |
| 设置/Launchpad/Monitor/系统控制图标 | 自行绘制同一视觉家族，或选有明确许可的通用图标资源 | 线宽、留白、光学尺寸统一；不要下载不明来源的 macOS 系统图标 |
| 玻璃纹理/噪点 | 自行生成可复用的无缝低对比纹理 | 在 DPI/色彩模式下测试重复纹和性能；记录生成方式和许可 |
| 应用内预览素材 | 从当前 pinned app icons 和真实系统 glyph 生成 | 预览必须与真实运行组件共用渲染代码，不用 A/B/C 假装最终图标 |
| 插件图标和主题 | 官方首发自行策展；社区资源逐项审核 | 记录来源、许可、版本和权限；不能因可下载就默认可信 |

## 技术路线建议

当前仓库是 Tauri 2 + React + Rust + Python sidecar。建议**暂时以它完成一条高质量纵向切片，不立即推倒重写**：先证明 Dock 点击穿透、任务栏共存、实际图标、窗口聚焦/还原、自动隐藏、DPI 和真实材质能达到体验门槛。Tauri 的优势是现成设置/Launchpad UI 和快速迭代；代价是 WebView2 与 sidecar 的全进程树占用、桌面材质裁剪限制，以及 Docklet/多窗口 surfaces 增加后的生命周期复杂度。

将领域状态、平台能力和 UI 渲染维持清楚边界：

1. **领域模型**：应用 ID、Pin、窗口快照、Dock 布局、主题、Shelf 条目、Docklet 清单和权限。
2. **Windows 平台层**：Shell 应用发现、AUMID、图标、窗口枚举/激活、显示器/DPI、托盘、热区、置顶和启动/退出。
3. **服务层**：设置迁移/备份、图标缓存、进程监控、Docklet 权限服务、故障日志。
4. **表现层**：Dock、Launchpad、窗口选择、Shelf、托盘弹出、设置和主题预览；纯组件不要直接模拟原生动作。

如果纵向切片在桌面材质、内存或输入边界方面过不了验收，再基于量测结果评估原生 Win32/DComp 或其它宿主路线。不要仅凭“原生更快/更好看”的假设重写，也不要把当前 Tauri 小 Dock 的成功等同于整个套件架构已验证。

## 验收门槛

### 构建和功能

- `npm run build`、Tauri 开发运行、Release 安装包构建均通过；冻结 sidecar 在干净安装环境正常启动。
- Rust、Vitest、Python 和 Playwright 测试全通过；Playwright 明确包含交互与错误状态，但原生行为仍须实机验收。
- 应用矩阵包含：未运行、单窗口前台/后台、最小化、多窗口、同名 EXE、Start Menu 子目录、MSIX/AUMID、卸载后残留 Pin。
- 任务栏矩阵包含：常驻/自动隐藏、底边点击、Dock 自动隐藏开关、全屏、最大化、Explorer 重启、睡眠唤醒、DPI/显示器变化。
- 所有用户操作有成功/失败反馈，设置和布局重启后保留；按键盘可到达、聚焦、调用和关闭核心模块。

### 美术、无障碍和性能

- 对比截图覆盖浅色、深色、高饱和、复杂纹理四种壁纸；100%、150%、200% 缩放；Sonoma/Tahoe/Minimal 预设；Dock 可见、悬停、菜单、Launchpad、窗口选择、设置和 reduced-motion 状态。
- 文字对比达到 WCAG AA：普通文字至少 4.5:1，大字与关键图形至少 3:1；实际透明合成后测量，不能只看 CSS 前景色。
- 默认状态不出现字母占位图标；品牌图标、系统控制图标和真实 app icons 可一眼区分且视觉重量一致。
- 鼠标放大及转场 p95 帧间隔不超过 16.7ms；冷启动可交互时间低于 1.5s；空闲 CPU 低于 1%；host 私有内存低于 30MB、包含 WebView2/sidecar 的进程树低于 200MB。每项按同一台目标硬件和多次中位数复测。
- 动画静止时没有无意义高频循环；Windows 减少动态效果启用时降低运动；键盘焦点、Escape 关闭与焦点恢复按交互契约工作。
